# 消费调解协议履约

跟踪网络消费调解协议中的退款、退换和维修义务是否真正完成。

## 业务事实

- 监管部门计划扩大在线消费纠纷解决机制覆盖
- 网络销售与直播带货是持续规范重点
- 消费纠纷需要多元化和源头化解

## 协作角色

- 消费者
- 平台客服
- 经营者
- 调解与监管人员

## 履约流程

- **协议生成**：`src/fulfillment.js` 的 `createAgreement` 把协议中的每项义务拆成责任方、期限、金额、收发地址和可接受证据，缺项即拒绝生成。
- **履约确认**：`applyEvent` 按真实顺序应用支付回调、物流回调与消费者确认。`event_id` 幂等，回调重放不会重复完成义务；`loss_id` 保证同一损失不会因多个渠道再次获得赔偿。部分退款累计到账才算完成；拒收不解除义务；退货丢失转入损失分担复核并释放关联退款义务；消费者撤销同意解除剩余义务；商家停业按违约升级。
- **凭证冲突复核**：消费者确认与客观凭证不一致时，义务先进入人工复核，复核结案前不算实际完成。
- **违约升级**：`sweepBreaches` 将超期未完成的义务标记为违约并记录升级条目。
- **协议保护**：已签协议不可由任何一方单独改写，变更须双方确认并留痕；敏感身份仅向当前经办人开放（`viewAgreement` 脱敏视图）。
- **状态口径**：每项义务区分已承诺（promised）、履行中（in_progress）、实际完成（fulfilled）与违约（breached），撤销或损失转移后为已解除（cancelled）。

## 目录说明

- `contracts/domain.schema.json` 定义共享资料的字段与基本约束。
- `contracts/fulfillment.schema.json` 定义调解协议与义务拆分的字段约束。
- `fixtures/context.json` 提供不含真实个人信息的公开样例。
- `fixtures/agreement-sample.json` 提供一份覆盖退款、退货、换新与维修义务的协议样例。
- 源码目录包含资料读取与基础校验逻辑，便于后续服务统一接入。

## 本地检查

运行项目自带测试可确认样例能够读取，领域标识、版本、参与者和记录结构完整。样例中不包含账号、密钥或连接凭据。
